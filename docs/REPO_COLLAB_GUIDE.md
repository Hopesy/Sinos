# 仓库协作约定

## 范围与验证

- 先核对分支、工作区变更和当前计划；保留用户及其他执行者的修改。提交、推送和发布按用户当前授权执行。
- 本地做源码审查与前端验证。Rust 检查、原生协议测试和五平台打包由 GitHub Actions 执行；本机 Rust 工具链已按用户 2026-11-13 的要求卸载，安装工具链需另行授权。
- 复用统一测试入口，缺陷回归先证明问题再修复；完整门禁见[发布规则](design/release.md)。界面目标需要真实交互证据，文档目标使用链接、消费者和配置契约检查。
- 普通静态检查可并行；资源密集型验证串行执行。本机曾因内存不足中断编译，缺少新证据时调整方法，而非重复启动同一任务。

## 文档维护

- `AGENTS.md` 是共享导航；模块事实写入[架构](ARCHITECTURE.md)，专题规则写入 `design/`。
- 同一持续目标使用一份[计划](PLANS_GUIDE.md)，目标、TODO、进度与接续摘要一起维护；同一任务沿用一份[history](HISTORY_GUIDE.md)。
- 用户修正立即更新约束；重要节点保存被测版本、证据、缺口和下一动作。决定变化保留原因及 `superseded_by` 指向。
- 旧文档切换后同步所有消费者，核验有效内容承接，再清理旧路径；不保留跳转副本或额外迁移账本。
- 详细日志、截图和过程脚本统一放 `.Sinos-temp/`。该目录保留的旧工作区恢复备份包含未提交状态，未经确认继续保留。
- 许可证、来源署名、运行资源及打包声明保持完整；文档目录结构不构成删除它们的依据。

## 会话导航

harness-run 通过项目本机的 `.claude/settings.json` 注册 SessionStart；该文件随 `.claude/` 忽略，不提交个人 Python 或 skill 安装路径。新机器使用实际安装位置运行 skill 的 `scripts/install_hooks.py --project <项目根> --host claude --session-cwd <实际会话目录>`。

配置变化需保留已有 hooks 和其他设置，并用 `--check`、stdin 合约测试核对。当前会话的模拟输入测试与下一次宿主 SessionStart 的真实注入分别报告；用户可通过 `/hooks` 查看和审核。
