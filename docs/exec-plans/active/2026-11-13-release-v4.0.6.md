## 操作与验证入口

1. 登录在本会话终端由用户完成：`! gh auth login -h github.com -p https -w -s workflow`。保持凭据在正常登录存储中。
2. 最终提交前核对工作区、版本、文档消费者及受影响验证；保留其他人的修改。开发/文档提交与最后的 release commit 分开，提交信息遵循现有约定。
3. 以最终 release commit 创建 `v4.0.6`，按发布规则推送 main 和 tag，跟踪同一 SHA 的 Review 与 Release。若候选 tag 推送后发现真实缺陷，保留草稿，修复使用新版本和新 tag。
4. GitHub Release quality 运行完整前端/Rust/原生协议门禁；五个平台打包后再检查最终程序。远程失败时保持未公开并修复。
5. 本机保留的资产工具已整理到 `.Sinos-temp/release-v4.0.6/verify-release-assets.mjs` 与 `check-msi-version.ps1`。下载到新的空目录，脚本放在其他目录运行；安装包只读取和校验。
6. 验证与公开后更新本计划及同一发布 history，报告链接、证据和未实测范围。

## 环境与实测缺口

- 本轮 native build 因主机内存压力中断；用户随后明确改用 GitHub 远程构建。已有旧版原生模拟服务结果不能代替当前发布提交的结果。
- Rust 测试临时目录放在仓库内时，Git 曾向上发现主仓库，造成 10 个隔离夹具失败。设置 `GIT_CEILING_DIRECTORIES` 为绝对 `.Sinos-temp` 目录后，完整套件 753 项通过；生产逻辑与断言未改。
- 用户报告真实 Claude 历史接续可用；Codex 曾因全局 npm 可选 Windows 依赖缺失启动失败。已按用户指示安装 Codex 0.167.2，并核对版本与平台二进制；本会话尚未执行真实账号续聊。
- 真实语音服务/麦克风、系统剪贴板/通知交互、物理手机及最新非 Windows 原生程序仍需对应环境。既有手机/Android 前端、模拟协议和本地中继测试分别按其范围报告。
