# 多会话内存优化记录

基线：`v4.0.4`，提交 `32bb74e00f736c1aab59970818a5081250190556`。
测试环境：Windows x64，本机 Playwright Chromium，生产模式 React。

## 改动

1. PTY 的移动端原始输出回放缓存同时受 2 MiB 和 2,000 批次上限约束。使用队列淘汰旧批次，保留最新输出。超大单批次按 UTF-8 字符边界截取末尾，仍对应一个输出序号；保存的字符串释放多余容量。
2. Claude、Codex、DSH 和终端会话投影接入可见性上下文。隐藏页面释放 Markdown 解析树与代码高亮子树；Claude 工具输出和差异视图同步释放渲染内容。会话所有者、交互控件、展开状态和滚动容器继续保留，恢复显示时使用最新消息。
3. 虚拟列表在同一测量帧中清除旧消息版本的尺寸记录，过滤过期测量回调。持续流式更新的缓存规模受当前消息集合约束。

PTY 限额控制移动端最近原始屏幕输出的回放窗口；终端的 5,000 行滚动缓冲、磁盘聊天记录和 CLI 进程的生命周期沿用原有行为。

## 原始输出缓存

每个会话写入 2,200 批 16 KiB 文本，旧实现保留末尾 2,000 批。记录字符串实际保留的字节数，排除容器元数据和分配器开销。

| 会话数 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 1 | 31.25 MiB | 2 MiB |
| 4 | 125 MiB | 8 MiB |
| 8 | 250 MiB | 16 MiB |

该负载下降 93.6%。小批次仍受 2,000 条限制。

复现：在仓库根目录执行：

```powershell
cargo test --locked retained_output_memory_profile -- --ignored --nocapture
```

## 前端页面

每个会话 96 条消息，其中 48 条 Markdown 回复，每条回复包含 70 个列表项。逐个访问所有标签，保留一个可见，其余隐藏，采样前执行垃圾回收。使用实际的 ClaudeConversation、MarkdownContent 和虚拟列表，原生会话传输与语法高亮服务由测试桩提供。

| 会话数 | JavaScript 堆：优化前 | 优化后 | DOM 节点：优化前 | 优化后 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 5.93 MiB | 5.95 MiB | 989 | 975 |
| 4 | 7.60 MiB | 7.11 MiB | 3,415 | 1,074 |
| 8 | 9.46 MiB | 8.31 MiB | 6,653 | 1,212 |

8 会话场景的堆占用下降 12.2%，DOM 节点减少 81.8%。从 1 个增加至 8 个会话的堆增量下降约 33%。隐藏页面的 Markdown 元素从 1,974 个降为 0。单次采样会随运行环境和垃圾回收时机产生小幅波动。

复现：在 `src-ui` 执行，输出 JSON 路径可按需修改：

```powershell
$env:SINOS_MEMORY_REF = 'v4.0.4'
node scripts/benchmark-session-memory.mjs before.json
Remove-Item Env:SINOS_MEMORY_REF
node scripts/benchmark-session-memory.mjs after.json
```

指定基线时脚本从 Git 对应提交读取三个参与测试的生产模块；当前版本使用工作区源文件。

## 回归覆盖与结果

- Rust：481 项通过，17 项默认跳过；额外运行上述手动缓存基准通过。新增回归覆盖持续输出、条数上限、字节淘汰后的移动回放序号，以及超大 Unicode 批次。
- 前端：原有 366 项 Vitest 和新增 2 项生命周期测试通过；53/53 回归脚本通过。
- 浏览器：23/23 脚本通过；增加隐藏页释放、后台消息更新、切回后的阅读位置、工具与差异展开状态检查。
- 10,000 次流式消息版本更新后，测量缓存只保留两条当前消息的尺寸。
- 前端构建、Lint、`cargo check --locked`、Clippy 正确性与可疑行为检查通过。

以上数据分别度量原始输出缓存和独立前端页面；整机任务管理器还会包含 WebView2、图形资源、各个 CLI 及工具子进程。此次基准使用合成对话，无真实工具账号任务。v4.0.4 标签保留原有发布内容，本次内存改动用于后续版本。
